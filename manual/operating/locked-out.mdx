# Not getting locked out

If Plex sign-in were the only way in, then a plex.tv outage, a revoked token, or a rebuilt Plex
server would lock you out of your own tool. A rebuild changes the `machineIdentifier` the
ownership check depends on. None of these are hypothetical.

So **Reaper always keeps at least one working local admin.** The last local admin cannot be
deactivated, and Plex sign-in is additive convenience, never the sole key.

<Callout tone="caution">
  **Create a local admin on day one.** Reaper logs a warning on every start until one exists.
  That warning is the whole of this page, delivered early.
</Callout>

## Three ways back in

<Steps>
  <Step title="The command line.">
    Works even if the UI is completely broken, because it talks to the database directly rather
    than through the app. Run `docker compose exec reaper reaper-admin --help` for the full
    command set. Creating an admin and resetting a password both live here.
  </Step>
  <Step title="Recovery mode.">
    Set `REAPER_RECOVERY=true` and restart. This has no setting in the UI on purpose: it has to
    work when the UI is what has locked you out.
  </Step>
  <Step title="The startup warning.">
    If no local admin exists at all, Reaper says so on every start, before you need it.
  </Step>
</Steps>

## Turn recovery back off

Recovery mode is a way in, so it is also a way in for anyone else who can reach the host.
Unset `REAPER_RECOVERY` and restart once you have a working admin again.
