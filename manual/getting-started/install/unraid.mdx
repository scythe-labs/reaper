# Unraid

Open the **Apps** tab, search for **Reaper**, and install it. Community Applications carries
the template.

Installing asks which channel you want. Take **Default**, which follows releases.

Not in the search results yet? The same template lives in the repository. Copy
`contrib/unraid/my-Reaper.xml` to:

```
/boot/config/plugins/dockerMan/templates-user/
```

Then add the container from the template dropdown in the Docker tab.

## Ownership

The template ships **`PUID` `99`** and **`PGID` `100`**, so the appdata folder stays owned by
`nobody:users`, which is what the rest of Unraid expects. Keep them.

<Callout tone="note">
  The container starts as root only to take ownership of its data folder, then drops to that
  user before it opens the database.
</Callout>

## Where the data goes

One path, Reaper's own database. The default in the template puts it under your appdata share.
Reaper needs no access to your media shares, so leave them unmapped.

## The dev channel

To run the dev channel, pick **dev** when you install. Dev builds change often. Releases are the
steadier channel.

The channel is only offered while installing. To move an install you already have, edit the
container and change the tag at the end of the **Repository** field from `:latest` to `:dev`.

Want both at once? Install Reaper a second time, pick **dev**, and give that one its own name,
port, and appdata folder. Two containers sharing one appdata folder share one database, so the
folder is the one you must not leave at its default.
