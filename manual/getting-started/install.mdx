# Install

Reaper ships as **one container**, and it needs no access to your media. It has no filesystem
delete path: only Sonarr and Radarr do. The only volume is its own small database.

<Callout tone="caution">
  **If you find yourself mounting your library, something is wrong.** Reaper never needs to see
  your media files.
</Callout>

## Docker

CI publishes an image on every push, so there is nothing to build:

```bash
docker compose up -d          # serves on http://localhost:8420
```

Use **`:dev`** for now. It tracks the `dev` branch, where the work lands. `:latest` follows
`main` once a release is cut.

To build from source instead, uncomment `build:` in `docker-compose.yml` and run
`docker compose up -d --build`.

Migrations run on every start, before the app accepts a connection. A half-migrated schema must
never serve traffic for a tool that deletes media.

## Unraid

Use the community template instead of composing by hand. Copy `contrib/unraid/my-Reaper.xml`
to `/boot/config/plugins/dockerMan/templates-user/`, then add the container from the template
dropdown.

Set `PUID` to `99` and `PGID` to `100`, so the appdata folder stays owned by `nobody:users`.

## File ownership

<Callout tone="note">
  **Ownership is handled for you.** The container starts as root only to take ownership of its
  data folder, then drops to an unprivileged user before it opens the database. A bind mount
  created owned by root just works.
</Callout>

Set `PUID` and `PGID` to choose that user. The default is `1000`. The app process itself never
runs as root.

To keep it off root entirely, pin `user: "1000:1000"` and create the folder owned by 1000
yourself.

## What to do next

Follow [First run](/getting-started/first-run) in order. The first account to sign in claims
the install, so it matters who does it.
